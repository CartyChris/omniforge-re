# Agents, skills, memory, retrieval and local-model tooling for OmniForge RE

Research date: 2026-10-18. "Stale" = no release or commit in ~18 months (before ~2025-04). Sources were fetched on that date through the sandbox egress proxy.

Method and limits worth knowing before reading the findings:
- GitHub REST API for repos was blocked by the proxy ("GitHub access to this repository is not enabled for this session"). Instead I did blobless shallow `git clone`s and read LICENSE files, READMEs and docs straight from the repos (cited as `github.com/<owner>/<repo>/blob/HEAD/<path>`), and used the npm registry (`registry.npmjs.org`) and PyPI JSON for versions, publish dates and licences. Star counts exist only where I could load the github.com page (9 repos).
- Blocked hosts (HTTP 403 on CONNECT or DNS failure): huggingface.co, hf.co, hf-mirror.com, modelscope.cn, ollama.com, registry.ollama.ai, agentclientprotocol.com, agentskills.io, developers.openai.com, ai.google.dev, geminicli.com, opencode.ai, docs.litellm.ai, ai-sdk.dev, openrouter.ai, mem0.ai, docs.letta.com, unpkg.com, cdn.jsdelivr.net, storage.googleapis.com, deps.dev, ungh.cc, img.shields.io. Hugging Face model cards and model weights could therefore NOT be fetched. Model sizes/licences below come from the fastembed model catalogue (a repo file), transformers.js docs, and search-result snippets, and are labelled accordingly.
- Reachable: api.github.com (rate-limit endpoint only), github.com via git and via the WebFetch tool, raw.githubusercontent.com, registry.npmjs.org, pypi.org, code.claude.com, developer.apple.com (JS shell only, no content).
- Throughput/size numbers marked "measured here" were produced on this sandbox (Linux x64, 4 vCPU Xeon 2.1 GHz, Node v22.22.0), not on a Mac.

## Ranked list: what OmniForge RE should integrate or adopt

### Takeaway
Highest value, lowest duplication: (1) a CLI-direct agent mode that spawns Claude Code / Codex / Gemini CLI / opencode / Cline / goose in a git worktree under an OS sandbox and returns a reviewable diff; (2) an Agent Skills (SKILL.md) + AGENTS.md loader in OmniForge's own harness, shipped with a short list of permissively licensed design/testing skills; (3) a local retrieval layer (small ONNX embedding model + brute-force/BM25 hybrid, Ollama `/api/embed` when present). Heavy agent frameworks, Python memory servers and gateways are not worth embedding.

### Cited Findings
Ranked recommendation list (rank, item, licence, why; evidence is in the sections below):
1. CLI-direct agentic adapter via JSONL/stream-json (Codex `exec --json`, Claude `-p --output-format stream-json`, Gemini `-p --output-format stream-json`, opencode `run --format json`, Cline `--json`, goose `run --output-format stream-json`) — no new dependency, spawns user-installed binaries; all emit structured events and can be pointed at a cwd. See section "CLI non-interactive modes".
2. `@anthropic-ai/sandbox-runtime` (`srt`) as the uniform OS sandbox/network allowlist around any CLI (Apache-2.0, beta research preview, macOS `sandbox-exec` + Linux bubblewrap) — [sandbox-runtime README](https://github.com/anthropics/sandbox-runtime/blob/HEAD/README.md); [LICENSE](https://github.com/anthropics/sandbox-runtime/blob/HEAD/LICENSE); [npm 0.0.80, 2026-10-16](https://registry.npmjs.org/@anthropic-ai%2fsandbox-runtime).
3. Agent Skills loader (progressive disclosure: catalogue of name+description at start, SKILL.md body on activation, resources on demand) plus AGENTS.md reading — spec and client guide are Apache-2.0 — [spec](https://github.com/agentskills/agentskills/blob/HEAD/docs/specification.mdx), [client guide](https://github.com/agentskills/agentskills/blob/HEAD/docs/client-implementation/adding-skills-support.mdx), [LICENSE Apache-2.0](https://github.com/agentskills/agentskills/blob/HEAD/LICENSE).
4. Bundled skill pack (all permissive, verified per-file): anthropics/skills `frontend-design`, `webapp-testing`, `web-artifacts-builder`, `theme-factory` (Apache-2.0); vercel-labs/agent-skills `react-best-practices`, `composition-patterns` (MIT in frontmatter); obra/superpowers `verification-before-completion`, `systematic-debugging`, `test-driven-development`, `writing-plans` (MIT); nextlevelbuilder/ui-ux-pro-max-skill data CSVs (MIT). Details and exclusions in the skills section.
5. Local retrieval over investigation evidence and code: `@huggingface/transformers` 4.3.1 (Apache-2.0) + `onnxruntime-web` 1.30.0 (MIT) in the browser with a 384-d model (bge-small-en-v1.5 or all-MiniLM-L6-v2), Ollama `/api/embed` in the sidecar when installed, a plain Float32Array brute-force index (no dependency) and MiniSearch/Orama for BM25 hybrid. Details in the embedding section.
6. "Run the agent CLI against a local model" presets: Ollama exposes an Anthropic Messages-compatible endpoint (`ANTHROPIC_BASE_URL=http://localhost:11434`, documented for Claude Code) — [Ollama docs](https://github.com/ollama/ollama/blob/HEAD/docs/api/anthropic-compatibility.mdx); Codex has `--oss --local-provider lmstudio|ollama` — [shared_options.rs](https://github.com/openai/codex/blob/HEAD/codex-rs/utils/cli/src/shared_options.rs).
7. ACP client (`@agentclientprotocol/sdk` 1.9.0, Apache-2.0) as phase 2, to get live permission prompts, file/terminal callbacks and one protocol for Claude (via `@agentclientprotocol/claude-agent-acp`), Codex (`@agentclientprotocol/codex-acp`), Gemini (`gemini --acp`), opencode (`opencode acp`), goose, Cline, OpenHands — [npm sdk](https://registry.npmjs.org/@agentclientprotocol%2fsdk), [ACP agents list](https://github.com/agentclientprotocol/agent-client-protocol/blob/HEAD/docs/get-started/_registry_agents.mdx).
8. Patterns to borrow without taking a dependency: aider `--auto-test/--test-cmd/--auto-lint` repair loop and git-commit-per-edit, mini-swe-agent's bash-only linear-history loop, screenshot-to-code prompt modules, dyad prompt files, Claude Code's `MEMORY.md` index + topic-file memory layout.
9. Optional, only if a concrete need appears: Vercel AI SDK (`ai` 7.0.143, Apache-2.0; has `ToolLoopAgent`, `@ai-sdk/mcp`, `@browser-ai/transformers-js`), `@modelcontextprotocol/sdk` (MCP client), mem0 OSS TypeScript (Apache-2.0) for LLM-extracted long-term memory, Cline SDK (0.0.x, unstable).
10. Do not adopt: LangGraph, Mastra, AutoGen (archived), OpenHands SDK, Letta, Graphiti/Zep, Cognee, LiteLLM/Portkey embedded (detect as external endpoints only), Roo Code, Void, Continue, gpt-engineer, hnswlib-wasm, voy, @xenova/transformers.

### Inferences
- The OmniForge gaps map cleanly: CLI-direct and diff review = items 1, 2, 7; skills loading = items 3, 4; retrieval = item 5; memory = file-based (item 8) before any library; model gateway = not needed because the provider layer already speaks OpenAI-compatible and Ollama (items 6, 10).
- No independent benchmark was found showing that any of the listed skills improves website-to-app output quality; the quality argument rests on the contents of the prompts (read in full for frontend-design and webapp-testing) and should be validated with OmniForge's own before/after screenshot comparison.

### Gaps
- Could not read hosted docs (agentclientprotocol.com, agentskills.io, developers.openai.com/codex, geminicli.com, opencode.ai) because of the egress policy; every CLI/protocol fact below comes from the repo copies of the docs or source code.

## What exact non-interactive invocation and structured output does each CLI offer, and how should OmniForge sandbox them and capture a diff?

### Takeaway
All five CLIs you named, plus Cline and goose, can run headless with a machine-readable event stream except aider (plain text only; use git for the diff). Claude Code, Codex, Gemini CLI and opencode each have a working-directory flag and an approval/permission policy, but only Codex (`--sandbox read-only|workspace-write|danger-full-access`) and Gemini (`-s`) expose their own sandbox switch in the docs I read; for a uniform guarantee wrap every CLI in `srt` and run it in a git worktree so the result is a `git diff`.

### Cited Findings
Claude Code (proprietary; BYO install):
- Headless: `claude -p "<prompt>" --output-format json|stream-json`; `stream-json` needs `--verbose` (add `--include-partial-messages` for token deltas); the last stream line is a `result` message with final text, cost and session metadata; `--json-schema '<schema>'` with `--output-format json` returns validated data in `structured_output` — [Claude Code headless docs](https://code.claude.com/docs/en/headless).
- First event is `system/init` (model, tools, MCP servers, plugins, plugin_errors, mcp_server_errors); retry events are `system/api_retry`; denials appear as `permission_denied` messages and `permission_denials` in the result when `--output-format stream-json` — [headless docs](https://code.claude.com/docs/en/headless).
- Permission control: `--allowedTools "Read,Edit,Bash(git diff *)"`, `--disallowedTools`, `--permission-mode acceptEdits|dontAsk|auto|...`, `--permission-prompts none` (v2.1.259+) for unattended runs. The docs warn a run with no explicit mode "takes the built-in starting permission mode, which can be auto", so always pass the mode explicitly — [headless docs](https://code.claude.com/docs/en/headless).
- Bounds and isolation flags: `--max-turns` (print mode), `--max-budget-usd` (client-side estimate, may be exceeded), `--add-dir`, `--no-session-persistence`, `--setting-sources`, `--strict-mcp-config --mcp-config`, `--fallback-model`, `--permission-prompt-tool` — [CLI reference](https://code.claude.com/docs/en/cli-reference).
- `--bare` skips auto-discovery of hooks, skills, commands, subagents, plugins, MCP servers, auto memory and CLAUDE.md and never reads OAuth/keychain (needs `ANTHROPIC_API_KEY`). Without `--bare`, a `-p` run executes the folder's `.claude/settings.json` hooks and connects its `.mcp.json` servers even in a never-trusted folder, with no trust dialog — security-relevant for rebuilt/untrusted repos — [headless docs](https://code.claude.com/docs/en/headless).
- Licence: repo LICENSE.md is "All rights reserved. Use is subject to Anthropic's Commercial Terms of Service" (not open source) — [LICENSE.md](https://github.com/anthropics/claude-code/blob/HEAD/LICENSE.md). npm `@anthropic-ai/claude-code` 2.1.302 published 2026-10-16 — [registry](https://registry.npmjs.org/@anthropic-ai%2fclaude-code).
- Reads AGENTS.md natively only from v2.1.277 and only when no CLAUDE.md/CLAUDE.local.md exists in or above the working directory (setting `claude-md-and-agents-md` changes that) — [memory docs](https://code.claude.com/docs/en/memory).

OpenAI Codex CLI (Apache-2.0):
- `codex exec [OPTIONS] [PROMPT]`; prompt may come from stdin (`-`); `--json` prints events as JSONL; `--output-schema FILE` constrains the final answer; `-o/--output-last-message FILE`; `--ephemeral`; `--ignore-user-config`; `--ignore-rules`; `--skip-git-repo-check`; subcommands `resume`, `fork`, `review` — [exec/cli.rs](https://github.com/openai/codex/blob/HEAD/codex-rs/exec/src/cli.rs).
- Shared flags: `--sandbox/-s read-only|workspace-write|danger-full-access`, `--cd/-C DIR`, `--add-dir DIR` (extra writable roots), `--worktree` (managed git worktree), `--model/-m`, `--image/-i`, `--profile/-p`, `--oss` with `--local-provider lmstudio|ollama`, `--approve-for-me` (auto-review in workspace-write), `--dangerously-bypass-approvals-and-sandbox` (alias `--yolo`) — [shared_options.rs](https://github.com/openai/codex/blob/HEAD/codex-rs/utils/cli/src/shared_options.rs), [sandbox enum](https://github.com/openai/codex/blob/HEAD/codex-rs/utils/cli/src/sandbox_mode_cli_arg.rs).
- JSONL event types: `thread.started`, `turn.started`, `turn.completed` (usage incl. cached and reasoning tokens), `turn.failed`, `item.started/updated/completed`, `error`; item types `agent_message`, `reasoning`, `command_execution` (command, aggregated_output, exit_code, status), `file_change` (changes[] with path and kind add/delete/update), `mcp_tool_call`, `collab_tool_call`, `web_search`, `todo_list`, `error` — [exec_events.rs](https://github.com/openai/codex/blob/HEAD/codex-rs/exec/src/exec_events.rs). The `file_change` items give OmniForge a live per-file change feed without parsing diffs.
- Official docs for exec and sandbox are only a pointer to developers.openai.com (blocked here) — [docs/exec.md](https://github.com/openai/codex/blob/HEAD/docs/exec.md).
- TypeScript SDK `@openai/codex-sdk` 0.163.0 (Apache-2.0) wraps the CLI and exchanges JSONL over stdin/stdout; `startThread({workingDirectory, skipGitRepoCheck})`, `run()`, `runStreamed()`, `outputSchema`, `resumeThread()`, image inputs; requires a git repo by default — [SDK README](https://github.com/openai/codex/blob/HEAD/sdk/typescript/README.md), [npm](https://registry.npmjs.org/@openai%2fcodex-sdk). `@openai/codex` 0.163.0 published 2026-10-15 — [npm](https://registry.npmjs.org/@openai%2fcodex).

Exit codes 0 success, 1 error, 42 input error, 53 turn limit — [headless.md](https://github.com/google-gemini/gemini-cli/blob/HEAD/docs/cli/headless.md).

Sandbox via flag, `GEMINI_SANDBOX` env or settings (`"tools.sandbox": "docker"`) — [sandbox.md](https://github.com/google-gemini/gemini-cli/blob/HEAD/docs/cli/sandbox.md). opencode (MIT; renamed sst/opencode to anomalyco/opencode):
- `opencode run [message..]` with `--format default|json` (raw JSON events), `--model provider/model`, `--agent`, `--dir`, `--file`, `--continue/--session/--fork`, `--attach URL`, `--auto` (auto-approve anything not explicitly denied) — [cli.mdx](https://github.com/anomalyco/opencode/blob/HEAD/packages/web/src/content/docs/cli.mdx).

- Permissions are per-tool `allow|ask|deny` in `opencode.json` (`edit`, `bash`, ...) — [permissions.mdx](https://github.com/anomalyco/opencode/blob/HEAD/packages/web/src/content/docs/permissions.mdx). It has no OS sandbox; `opencode acp` speaks ACP — [acp.mdx](https://github.com/anomalyco/opencode/blob/HEAD/packages/web/src/content/docs/acp.mdx).
- 216.3k stars, MIT — [repo page](https://github.com/anomalyco/opencode); npm `opencode-ai` 1.19.3 (2026-10-16), MIT — [registry](https://registry.npmjs.org/opencode-ai).
- Kilo Code's CLI is a fork of OpenCode (MIT) — [Kilo README](https://github.com/Kilo-Org/kilocode/blob/HEAD/README.md).

aider (Apache-2.0):
- `aider --message "<text>" [files]` (or `--message-file`) applies the edit and exits; `--yes-always`/`--yes`, `--no-auto-commits`, `--dry-run`, `--auto-test --test-cmd`, `--auto-lint --lint-cmd`, `--edit-format`, `--architect`; Python API `Coder.create(...).run(...)` — [scripting.md](https://github.com/Aider-AI/aider/blob/HEAD/aider/website/docs/scripting.md), [options.md](https://github.com/Aider-AI/aider/blob/HEAD/aider/website/docs/config/options.md). Cline and goose (both headless with structured output):
- Cline README: headless CLI for CI/CD with `cline --json "<task>"` piped to jq; Apache-2.0; 70.5k stars; TypeScript `@cline/sdk` (`new Agent({providerId, modelId, systemPrompt, tools}).run(...)`) at 0.0.95 (Apache-2.0) — [README](https://github.com/cline/cline/blob/HEAD/README.md), [sdk README](https://github.com/cline/cline/blob/HEAD/sdk/README.md), [npm](https://registry.npmjs.org/@cline%2fsdk).

Sandboxing and diff capture:
- `srt` enforces filesystem (denyRead/allowWrite/denyWrite) and network (allowedDomains) policy on arbitrary processes with `sandbox-exec` on macOS and bubblewrap on Linux; configured in `~/.srt-settings.json`; marked "Beta Research Preview" — [README](https://github.com/anthropics/sandbox-runtime/blob/HEAD/README.md).
- Codex's own `workspace-write` mode and Gemini's `-s` give built-in sandboxes; Claude Code, opencode and aider rely on permission prompts/rules rather than an OS sandbox in the headless docs read here — [Codex flags](https://github.com/openai/codex/blob/HEAD/codex-rs/utils/cli/src/shared_options.rs), [Gemini sandbox](https://github.com/google-gemini/gemini-cli/blob/HEAD/docs/cli/sandbox.md), [Claude headless](https://code.claude.com/docs/en/headless).

### Inferences
- Recommended runner contract (not from a source; design proposal): (a) copy or `git worktree add` the approved folder into a scratch dir and commit a baseline (or `git init` if not a repo, which Codex also needs unless `--skip-git-repo-check`); (b) run `srt` around the CLI with allowWrite limited to that dir and a network allowlist of the model host(s); (c) pass explicit bounds (`--max-turns`, `--max-budget-usd`, Codex `--sandbox workspace-write`, Gemini `--approval-mode auto_edit`, opencode permission JSON); (d) parse the JSONL for progress; (e) when the process exits compute `git add -A && git diff --binary <base>`; (f) show it in the existing diff-and-accept panel and apply to the real folder only after approval (`git apply --3way`).
- Use `claude --bare` plus explicit `--mcp-config`/`--append-system-prompt-file` for reproducibility and to avoid executing hooks from a cloned, untrusted repo; if skills should still load, pass them with `--add-dir` (bare mode loads skills from `--add-dir/.claude/skills`).
- A single normalizer (`CliEvent = progress | tool | file_change | message | usage | error | done`) with four small adapters (claude, codex, gemini, opencode; Cline and goose are near-identical) is cheaper than adopting an agent framework; aider needs a text-only adapter plus the git diff.
- Gemini CLI should be offered only for API-key users; do not build on its "free Google login" path given the Antigravity transition.

### Gaps
- opencode `--format json` and Cline `--json` event schemas were not read (only that the flags exist); the SDK type file `types.gen.ts` would define them.
- Codex's default approval/sandbox policy under `exec` was not verifiable (docs host blocked); always pass `--sandbox` explicitly.
- No test run of any CLI was possible (binaries not installed; model APIs unreachable/unauthenticated), so flag spellings are from source/docs only.

## Which skills/prompt packs are permissively licensed and would improve generated-app quality?

### Takeaway
The Agent Skills format is an Apache-2.0 open spec, and Anthropic's `frontend-design`, `webapp-testing`, `web-artifacts-builder` and `theme-factory` skills are Apache-2.0 (per-skill LICENSE.txt), as are obra/superpowers (MIT) and Vercel's `react-best-practices`/`composition-patterns` (MIT frontmatter). Avoid the proprietary docx/pdf/pptx/xlsx skills, awesome-claude-code (CC BY-NC-ND) and anything copied from the claude-code repo's plugins directory.

### Cited Findings
Format and convention:
- SKILL.md = YAML frontmatter (`name` 1-64 chars lowercase/hyphen and equal to the directory name; `description` 1-1024 chars; optional `license`, `compatibility`, `metadata`, experimental `allowed-tools`) + Markdown body; optional `scripts/`, `references/`, `assets/` — [specification](https://github.com/agentskills/agentskills/blob/HEAD/docs/specification.mdx).
- Client guide: three-tier progressive disclosure (catalogue ~50-100 tokens per skill; body under ~5000 tokens; resources on demand), scan project and user scopes in both a client-specific dir and `.agents/skills/`, optionally `.claude/skills/`; project skills override user skills; gate project skills on a trust check because the repo may be untrusted; be lenient on malformed YAML — [adding-skills-support.mdx](https://github.com/agentskills/agentskills/blob/HEAD/docs/client-implementation/adding-skills-support.mdx).
- Adopters verified in their own docs: opencode loads `SKILL.md` from `.opencode/skills`, `.claude/skills`, `.agents/skills` and `~/` equivalents — [skills.mdx](https://github.com/anomalyco/opencode/blob/HEAD/packages/web/src/content/docs/skills.mdx); Gemini CLI has `gemini skills install/list/enable` — [cli-reference](https://github.com/google-gemini/gemini-cli/blob/HEAD/docs/cli/cli-reference.md); Codex lists a skills doc and `$skill-installer` — [openai/skills README](https://github.com/openai/skills/blob/HEAD/README.md); the spec repo maintains a client showcase (`docs/clients.mdx`).
- AGENTS.md: "a simple, open format for guiding coding agents", a README for agents; repo licence MIT, Copyright OpenAI — [agentsmd/agents.md README](https://github.com/agentsmd/agents.md/blob/HEAD/README.md), [LICENSE](https://github.com/agentsmd/agents.md/blob/HEAD/LICENSE). Supported by opencode ([rules.mdx](https://github.com/anomalyco/opencode/blob/HEAD/packages/web/src/content/docs/rules.mdx)), Gemini via config, Claude Code conditionally (see CLI section), Codex ([docs/agents_md.md](https://github.com/openai/codex/blob/HEAD/docs/agents_md.md) pointer).

## Which embedding stack fits (1) a browser SPA with no server and (2) a Bun-compiled Node sidecar?

### Takeaway
Browser: `@huggingface/transformers` (Apache-2.0) with a 384-dimension MiniLM/BGE-small model in a Web Worker (WebGPU when available, WASM fallback), a plain Float32Array brute-force index in IndexedDB and a BM25 side index. Sidecar: prefer Ollama's `/api/embed` if installed, otherwise transformers.js on onnxruntime-node (verify Bun --compile packaging first), with brute-force search or sqlite-vec under Node; usearch/LanceDB/PGlite are heavier than a few-thousand-chunk workload needs.

### Inferences
- Browser default: bge-small-en-v1.5 or all-MiniLM-L6-v2 at q8/int8 (~tens of MB, 384-d), plus potion-base-8M (30 MB, MIT) as a no-WebGPU/low-memory fallback; one-time model download is the dominant cost, so cache in Cache Storage/IndexedDB and show progress. EmbeddingGemma is higher quality per its card but the Gemma licence and 4x size make it opt-in only.
- At OmniForge scale (investigation evidence and a repo's chunks, likely under 50k chunks) brute force is enough: 384-d x 50k vectors is ~77 MB of Float32 and ~45 ms/query even unoptimized in JS, so a dependency-free index with IndexedDB persistence (browser) or a SQLite BLOB/file (sidecar) avoids the Bun-extension problem. Add sqlite-vec only on Node-run paths if filtered KNN or on-disk size matters; avoid usearch/LanceDB until corpora exceed ~200k chunks.
- Hybrid ranking (BM25 via MiniSearch/Orama + cosine, fused by reciprocal rank) will matter more than the ANN structure for code and HTTP evidence where identifiers are exact-match terms; embed ~256-token chunks to stay inside MiniLM's limit.
- Real embedding throughput on Apple Silicon could not be measured; plan for first-index latency in minutes for large repos on WASM and use WebGPU/Ollama when present.

## What is the state of ACP, the Claude Agent SDK and the Codex SDK as integration surfaces?

### Takeaway
ACP is a mature, Apache-2.0, JSON-RPC-over-stdio protocol with a stable v1, a v2 draft and a large agent list (Claude, Codex, Gemini, opencode, goose, Cline, OpenHands and more), so OmniForge can act as an ACP client over its local bridge. The Codex SDK is Apache-2.0 and wraps the CLI; the Claude Agent SDK's TypeScript package is under Anthropic's Commercial Terms (Python is MIT), and Anthropic forbids third parties offering claude.ai login through it, so use API keys or the user's own logged-in CLI.

### Cited Findings
ACP:
- "The current stable ACP protocol version is `1`"; schema repo is Apache-2.0; official libraries for Kotlin, Java, Python, Rust and TypeScript — [README](https://github.com/agentclientprotocol/agent-client-protocol/blob/HEAD/README.md). Latest changelog entry 1.12.0 on 2026-10-16 includes unstable-v2 items; a v2 draft is announced (`docs/announcements/acp-v2-draft.mdx`), and the TS SDK exposes v2 only via an explicit `experimental/v2` import and warns it "may change incompatibly in any SDK release" — [CHANGELOG](https://github.com/agentclientprotocol/agent-client-protocol/blob/HEAD/CHANGELOG.md), [TS SDK README](https://github.com/agentclientprotocol/typescript-sdk/blob/HEAD/README.md).
- Message flow: client `initialize` (negotiate versions/capabilities), optional `authenticate`, `session/new` or `session/load`, then `session/prompt` with agent `session/update` notifications, agent-initiated file operations and permission requests, `session/cancel`; JSON-RPC 2.0 over stdio with agents as client subprocesses — [overview.mdx](https://github.com/agentclientprotocol/agent-client-protocol/blob/HEAD/docs/protocol/v1/overview.mdx). Protocol docs include pages for file-system, terminals, tool-calls, session-modes, slash-commands and agent-plan — [v1 docs tree](https://github.com/agentclientprotocol/agent-client-protocol/tree/HEAD/docs/protocol/v1).
- Packages: `@agentclientprotocol/sdk` 1.9.0 (Apache-2.0, 2026-10-16); older `@zed-industries/agent-client-protocol` is deprecated/renamed — [registry](https://registry.npmjs.org/@agentclientprotocol%2fsdk), [old](https://registry.npmjs.org/@zed-industries%2fagent-client-protocol). Python SDK `agent-client-protocol` 0.12.1 (2026-08-16) — [PyPI](https://pypi.org/pypi/agent-client-protocol/json).
- Adapters: `@agentclientprotocol/claude-agent-acp` 0.93.0 (Apache-2.0, 2026-10-16; wraps the Claude Agent SDK; supports permission requests, terminals, MCP servers, subagent sessions, slash commands); `@agentclientprotocol/codex-acp` 2.2.2 (Apache-2.0, 2026-10-10; `npx -y @agentclientprotocol/codex-acp`; bundles a compatible `@openai/codex`; ChatGPT/API-key/custom-gateway auth, sandbox and approval config); old `@zed-industries/claude-code-acp` and `codex-acp` are deprecated — [claude-agent-acp README](https://github.com/agentclientprotocol/claude-agent-acp/blob/HEAD/README.md), [codex-acp README](https://github.com/agentclientprotocol/codex-acp/blob/HEAD/README.md), [npm claude](https://registry.npmjs.org/@agentclientprotocol%2fclaude-agent-acp), [npm codex](https://registry.npmjs.org/@agentclientprotocol%2fcodex-acp).
- Native ACP agents: Gemini CLI `--acp` (core in `packages/cli/src/acp/acpClient.ts`), opencode `opencode acp`, plus goose, Cline, OpenHands, Cursor, Copilot CLI (public preview), Kimi, Qwen Code, Kiro and others — [Gemini acp-mode.md](https://github.com/google-gemini/gemini-cli/blob/HEAD/docs/cli/acp-mode.md), [opencode acp.mdx](https://github.com/anomalyco/opencode/blob/HEAD/packages/web/src/content/docs/acp.mdx), [agents list](https://github.com/agentclientprotocol/agent-client-protocol/blob/HEAD/docs/get-started/_registry_agents.mdx).
- ACP is client-subprocess based; Zed is GPL-3.0 for the app and Apache-2.0 for parts (both LICENSE files present) but OmniForge only needs the protocol and SDK — [zed repo](https://github.com/zed-industries/zed).

Claude Agent SDK:
- TypeScript `@anthropic-ai/claude-agent-sdk` 0.3.302 (2026-10-16); licence "SEE LICENSE IN README.md" which says use is governed by Anthropic's Commercial Terms of Service, "including when you use it to power products and services that you make available to your own customers and end users" — [registry](https://registry.npmjs.org/@anthropic-ai%2fclaude-agent-sdk), [README](https://github.com/anthropics/claude-agent-sdk-typescript/blob/HEAD/README.md). Python `claude-agent-sdk` 0.2.168 is MIT — [PyPI](https://pypi.org/pypi/claude-agent-sdk/json), [LICENSE](https://github.com/anthropics/claude-agent-sdk-python/blob/HEAD/LICENSE).
- Docs: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication methods"; SDK loads skills, commands and memory from `.claude/` and `~/.claude/` like Claude Code, and supports permissions, subagents, MCP, sessions and plugins — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview).
- Telemetry/data note in the SDK README: usage data and feedback are collected per Anthropic policies — [README](https://github.com/anthropics/claude-agent-sdk-typescript/blob/HEAD/README.md).

Codex SDK: see CLI section (Apache-2.0, wraps `codex` over JSONL, Node 18+, git repo required unless skipped) — [README](https://github.com/openai/codex/blob/HEAD/sdk/typescript/README.md).

### Inferences
- Integration decision: use `claude -p` (user's own logged-in install) or ACP/SDK with the user's API key; do not ship OmniForge-owned Claude subscription login. Bundling the TS Agent SDK package is a Commercial Terms matter, so prefer spawning the user's CLI or the Apache-2.0 `claude-agent-acp` (which still depends on the proprietary SDK).
- ACP vs JSONL: JSONL is simplest and sufficient for fire-and-forget runs with a diff gate; ACP adds interactive per-action approvals, file-system and terminal callbacks (so OmniForge can keep the "approved folder" boundary itself by serving fs requests) and one code path for ~20 agents. Do JSONL first, ACP second.
- The v1 stable / v2 draft split means pinning `@agentclientprotocol/sdk` to the stable entry point and treating v2 as out of scope.

### Gaps
- Exact ACP client-side method names (e.g. permission request, fs read/write, terminal create) were not read from the schema; only the overview and page list were.
- Not tested: whether `claude-agent-acp` or `codex-acp` run inside a Bun-compiled sidecar's child process environment (they run as separate Node processes via `npx`).

## Which agent memory approach is feasible offline and in-browser?

### Takeaway
File-based memory (an index plus topic notes, loaded by the harness and searchable by the same embedding index) is the right first step; mem0's TypeScript OSS is the only library with a realistic offline path, and Letta, Zep/Graphiti and Cognee are Python-centred, server-oriented or retired.

### Cited Findings
- Claude Code auto memory is plain files: a `MEMORY.md` index (one line per memory, loaded into every session) plus one topic file per memory under `~/.claude/projects/<project>/memory/`, shared across worktrees of a repo and machine-local — [memory docs](https://code.claude.com/docs/en/memory). Gemini CLI "Auto Memory" mines past session transcripts for durable facts and proposes memory updates as unified-diff patches and reusable skills that the user reviews before they apply — [auto-memory.md](https://github.com/google-gemini/gemini-cli/blob/HEAD/docs/cli/auto-memory.md).
- mem0 (Apache-2.0; head 2026-10-14): npm `mem0ai` 3.3.1 (2026-09-25) has a TypeScript OSS implementation (`mem0-ts/src/oss`) with embedders for Ollama, LM Studio, FastEmbed, Hugging Face, OpenAI and others, a built-in `memory` vector store (source comments say file-based stores use SQLite) plus Qdrant/pgvector/etc. connectors, with `better-sqlite3` as a dependency; the Python package `mem0ai` is 2.2.1 (version numbers differ between ecosystems). The "April 2026" algorithm is single-pass ADD-only LLM extraction with entity linking and multi-signal retrieval; the README notes the published benchmark scores reflect the managed platform's proprietary optimizations (sentence truncated in my capture) — [README](https://github.com/mem0ai/mem0/blob/HEAD/README.md), [embeddings dir](https://github.com/mem0ai/mem0/tree/HEAD/mem0-ts/src/oss/src/embeddings), [npm](https://registry.npmjs.org/mem0ai), [PyPI](https://pypi.org/pypi/mem0ai/json).
- Letta: README says the current source lives in `letta-ai/letta-code` (a coding-agent harness and App Server) and the retired Letta V1 API server is only on an `archive` branch; npm `@letta-ai/letta-code` 0.34.16, `@letta-ai/letta-agent-sdk` 0.8.46, `@letta-ai/letta-client` 1.12.1, all Apache-2.0 — [letta README](https://github.com/letta-ai/letta/blob/HEAD/README.md), [letta-code npm](https://registry.npmjs.org/@letta-ai%2fletta-code).
- Zep/Graphiti: `graphiti-core` 0.31.1 (Apache-2.0, 2026-10-15), Python >=3.10, needs Neo4j, FalkorDB or Neptune (Kuzu support is deprecated because "the upstream Kuzu project is no longer maintained"; embedded FalkorDBLite needs Python 3.12+) and defaults to OpenAI for LLM and embeddings; JS package `@getzep/zep-cloud` 4.0.0 is a cloud client with no licence field — [README](https://github.com/getzep/graphiti/blob/HEAD/README.md), [PyPI](https://pypi.org/pypi/graphiti-core/json), [zep-cloud](https://registry.npmjs.org/@getzep%2fzep-cloud).
- Cognee: `cognee` 1.6.5 (Apache-2.0, 2026-10-16), Python; "runs locally for free - no API key required" using local GLiNER extraction and a local embedding model (downloaded on first use) — [README](https://github.com/topoteretes/cognee/blob/HEAD/README.md), [PyPI](https://pypi.org/pypi/cognee/json).
- Mastra Memory: working memory, semantic recall (needs a vector store and embedder such as `@mastra/fastembed` + `@mastra/libsql`), observational memory; semantic recall is off by default; depends on the 76 MB Mastra core — [semantic-recall.mdx](https://github.com/mastra-ai/mastra/blob/HEAD/docs/src/content/en/docs/memory/semantic-recall.mdx).

### Inferences
- Browser-feasible: file/IndexedDB notes + embedding index; mem0-ts "memory" vector store could also run in a browser only if its Node dependencies (`better-sqlite3`) are bypassed, which was not tested. LLM-based extraction of memories needs a model call, so offline operation requires a local model (Ollama/LM Studio).
- Proposed OmniForge design: per-investigation and per-project memory directories with a `MEMORY.md` index and typed topic notes (user preferences, site-specific quirks, decisions, failed approaches), written through an agent `remember` tool and shown for approval in the UI (Gemini's review-before-apply idea); retrieval via the same embedding index; no Python services.

### Gaps
- mem0-ts browser compatibility and exact default storage path not verified; benchmark claims (LoCoMo, LongMemEval) are vendor claims and not independently checked.

## Which model gateways, free-tier clouds and local runtimes should OmniForge auto-detect?

### Takeaway
